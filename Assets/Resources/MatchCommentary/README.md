# 경기 중계 문장 작성

`commentary_events.json`에서 상황별 문장 후보를 수정합니다. 각 상황의 후보 중 하나가 무작위로 선택됩니다.

## 문장과 전달값

`text`의 `{%1}`은 `parameters`의 첫 번째 값, `{%2}`는 두 번째 값으로 바뀝니다.

```json
{
  "text": "{%1}의 공격!",
  "parameters": ["{teamLabel}"],
  "character": "player",
  "side": "{side}",
  "resourcePath": "Image/MatchPortraits/player_attack_{side}"
}
```

위 문장은 아군 공격이면 `아군의 공격!`, 상대 공격이면 `상대의 공격!`이 됩니다. `parameters`에 `"힘찬 스파이크"`처럼 고정 문구를 넣을 수도 있습니다.

현재 문장들은 아래 순서를 공통으로 사용합니다. 마지막으로 쓰는 번호까지만 `parameters`에 넣으며, 중간 항목은 생략하지 않습니다.

| 자리 | 전달값 | 의미 |
| --- | --- | --- |
| `{%1}` | `{teamLabel}` | 이번 행동을 한 팀: 아군 또는 상대 |
| `{%2}` | `{opponentLabel}` | 그 반대 팀: 상대 또는 아군 |
| `{%3}` | `{player}` | 행동한 선수 이름. 선수가 없으면 팀 이름 |
| `{%4}` | `{target}` | 대상 선수 이름. 선수가 없으면 반대 팀 이름 |
| `{%5}` | `{set}` | 현재 세트 번호 |
| `{%6}` | `{score}` | 현재 점수: 아군 : 상대 |
| `{%7}` | `{setScore}` | 세트 승수: 아군 : 상대 |

`parameters`의 값을 먼저 경기 정보로 바꾼 다음 문장에 한 번만 넣습니다. 전달한 값 안의 `{%숫자}`를 다시 해석하지 않습니다. 없는 번호는 원문 그대로 남으므로 문장 번호와 배열 길이를 맞춰야 합니다.

기존 `{team}`, `{opponent}`, `{player}`, `{target}`, `{set}`, `{score}`, `{setScore}` 문법도 유지됩니다. `{team}`과 `{opponent}`는 설정된 팀 이름이고, `{teamLabel}`과 `{opponentLabel}`은 아군/상대 표기입니다.

## 그림 방향

`side`와 `resourcePath`에는 `{side}`를 사용합니다. 코드가 이번 행동의 팀을 보고 아군은 `left`, 상대는 `right`로 바꿉니다. 득점 안내는 득점한 팀, 세트·경기 종료는 승리한 팀이 기준입니다. 범실 안내는 실수한 팀이 기준입니다.

이미지 경로에는 `Assets/Resources/`와 `.png`를 쓰지 않습니다. 새 중계가 나타날 때 이전 그림은 양쪽 모두 숨기고, 현재 쪽의 그림만 표시합니다.
